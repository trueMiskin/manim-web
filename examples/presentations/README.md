# Presentations

The optional `manim-web/reveal` entry provides authored topics, animated checkpoint slides, selectable settled text, and one shared print path. Core `manim-web` does not import Reveal.

Start with `slide` for content: prose, formulas, code, lists, images, columns, and named builds. The basic starter combines this declarative content with custom animated scenes in one grouped deck. Use `defineSlide` when a slide needs custom animation; it shares the same layout and playback system. The lesson, text, and mixed examples explore that API further, while the tech demo also includes manually positioned scientific animations.

Each example directory is a standalone Vite project: its `package.json` declares its dependencies, and its TypeScript imports only public `manim-web` and `manim-web/reveal` APIs. Copy any one of the directories below to start your own project; its source, assets, Vite configuration and TypeScript configuration travel together.

For development in this repository, run `npm ci`, then `npm run dev`, and open:

- `/examples/presentations/basic/index.html`: the combined starter generated by `slides init`, with seven topics and 18 checkpoints. [deck.ts](basic/deck.ts) groups declarative opening slides, geometry, text animations, selectable code with line numbers and copying, a moving point with live values, matrix–vector multiplication, and a lesson with formulas, a captioned image in columns, and named bullet builds. [main.ts](basic/main.ts) mounts the deck with one helper.
- `/examples/presentations/lesson/index.html`: custom animations for an ordinary math lesson. Two short scenes build a gradient-descent explanation with wrapping prose, inline math, bullet reveals, named formula parts, a transformation, and a plot in a second column. A static Markdown recap includes display math.
- `/examples/presentations/text/index.html`: writing, Unicode graphemes, emphasis, removal, and text selection, with automatic placement for the animated text.
- `/examples/presentations/mixed/index.html`: Markdown, HTML, SVG, video/audio with print replacements, backgrounds, and a rotating 3D torus with automatically laid-out text.
- `/examples/presentations/tech-demo/index.html`: the [tech demo](tech-demo/README.md), with eight topics and 17 checkpoints covering shape and formula morphs, bouncing rays, deforming surfaces, heatmaps and optimization. Seven 2D topics use `defineSlide` for shared titles and checkpoints while keeping geometry and captions in their original coordinates. The 3D topic uses a direct `SceneDefinition`. A matching Python scene is included. Its bundled light/dark palettes demonstrate the standard color selector and custom diagram colors.
- `/examples/presentations/low-level/index.html`: one [small direct scene](low-level/scene.ts) with manual positioning, drawing a circle and moving it. Use this as a reference for the underlying API.

Every presentation example includes a **Colors** selector for light/dark palettes. The basic starter selects its initial `palette` and shared `theme` in [deck.ts](basic/deck.ts). Edit [basic/palettes.ts](basic/palettes.ts) to customize the standard colors or diagram roles such as grid and orbit. Add matching named colors to both palettes, then use `s.colors` when constructing custom graphics.

See the [authoring API](API.md) for scene steps, embedded playback, text contracts and capture options, including [named color palettes](API.md#switch-color-palettes). Switching rebuilds the slides and print snapshots without changing typography.

For content pages, declare blocks with `slide`, as in [intro.ts](basic/intro.ts), [bullets.ts](basic/bullets.ts), and [code.ts](basic/code.ts). Named builds reveal selected blocks or individual bullet items while preserving the layout. Code defaults to line numbers and a Copy button; paused selection and copying exclude the line-number gutter. [Code highlighting](API.md#code-blocks) uses bundled Shiki grammars and inherits the slide palette. The lesson topic in [deck.ts](basic/deck.ts) also demonstrates formula transformations with `slot` and `transformMath`, and columns with an image.

For custom animation, `defineSlide({ title }, async s => { ... })` handles layout and preparation. Declare `s.paragraph(...)`, `s.math(...)`, and `s.bullets(...)` before the first `s.step(...)`, then reveal them at the desired pauses. Hidden content reserves space; paragraphs wrap, and overflow produces an error. Use `s.columns(...)` and `region.place(...)` for diagrams, and ordinary Manim animations through `s.play(...)`. Read [scene.ts](basic/scene.ts) for a short animation, [gradient.ts](lesson/gradient.ts) for teaching checkpoints, then [quadratic.ts](lesson/quadratic.ts) for a formula transformation.

Use Node 20.x (20.19 or later), or Node 22.12 and later, as required by Vite 8. For this unreleased checkout, install the packed library as described below first. In a copied example directory, install the package dependencies and run its scripts:

```sh
npm install
npm run typecheck
npm run dev
```

Install Chromium before building a portable site or exporting a PDF:

```sh
npx playwright install chromium
npm run build
npm run pdf
```

The examples declare the npm package as their dependency. These presentation APIs include changes that are not published yet (including declarative content slides and the tech demo’s curve-resampling export), so use a packed build of this checkout until a release includes them. Build and pack the library, then install that tarball in the copied example before running its scripts:

```sh
# In the library repository:
npm ci
npm run build
npm pack --pack-destination /tmp

# In the copied example (use the filename printed by npm pack):
npm install /tmp/manim-web-0.3.24.tgz
```

This tests the same public package entry points and bundled code a published consumer uses. Do not copy the repository's shared `examples/presentations/vite.config.ts` or `tsconfig.json` into a standalone project: the individual examples already contain independent versions.

Repository development can resolve the public package imports to live source. The root `npm run dev` does this automatically; pass the shared Vite configuration explicitly when building or exporting a repository example:

```sh
node scripts/slides.mjs build examples/presentations/lesson --config examples/presentations/vite.config.ts
node scripts/slides.mjs pdf lesson.pdf examples/presentations/lesson --config examples/presentations/vite.config.ts
```

The shared configuration supplies source aliases and the Typia build plugin, so these commands test changes before publishing. A standalone example uses the compiled npm package and does not need that plugin. `slides init my-presentation` copies the combined basic starter from an installed `manim-web` package. Edit its `deck.ts`, `intro.ts`, and `bullets.ts` for content, and its animation modules for custom scenes. Every example remains available to copy independently.

`slides build` runs Vite, visits the built deck in Chromium, captures all authored checkpoint states, and packages content-addressed images plus `manim-handout.json` in `dist/`. Serve that directory as a static site. The browser eagerly prepares those print assets, while live scene modules load on navigation. `slides pdf` exports the same flat handout through Chromium. Ordinary viewing and authoring need JavaScript only; Python and a rendering server are not required.

To **share one runtime between presentations**, use the bundled [basic](basic/) and [lesson](lesson/) examples. Build and pack this checkout as shown above, then run the following from the repository root. This copies both examples into a fresh temporary directory and installs the same compiled library in each copy; use the tarball filename printed by `npm pack`:

```sh
demoDir=$(mktemp -d)
cp -R examples/presentations/basic "$demoDir/basic"
cp -R examples/presentations/lesson "$demoDir/lesson"

# Create the runtime once, then export the basic example.
cd "$demoDir/basic"
npm install /tmp/manim-web-0.3.24.tgz
npx slides runtime --outDir ../site/runtime/v1
npm run build -- --runtime ../site/runtime/v1 --outDir ../site/basic --emptyOutDir

# Add the lesson example without rebuilding basic or the runtime.
cd "$demoDir/lesson"
npm install /tmp/manim-web-0.3.24.tgz
npm run build -- --runtime ../site/runtime/v1 --outDir ../site/lesson --emptyOutDir
```

Both examples already define `"build": "slides build"` in their [basic/package.json](basic/package.json) and [lesson/package.json](lesson/package.json); `--` forwards the extra arguments to that script. Use each example's own Vite configuration with the compiled package for this workflow. The shared-runtime build does not use the repository's live-source aliases. Chromium or an installed Chrome is required for capture, as with ordinary `slides build`.

The shared directory contains the library and its runtime dependencies. Each deck output contains its own content, media, and generated handout assets. The default runtime URL is relative to the deck's actual output directory. With the starter's `base: './'`, deploy the whole `site/` directory under any website prefix while preserving this layout:

```text
site/
  runtime/v1/ # Shared runtime, built once
  basic/      # Basic example and its handouts
  lesson/     # Lesson example and its handouts
```

From the copied `lesson/` directory, run `python3 -m http.server 8000 --directory ../site`, then open `http://localhost:8000/basic/` or `http://localhost:8000/lesson/`. For offline viewing, copy the whole `site/` directory and serve it the same way. A deck folder alone requires its referenced runtime to remain available. PDF export accepts the same options and rebuilds the selected deck before printing:

```sh
# In the copied lesson/ directory, after stopping the HTTP server:
npx slides pdf lesson.pdf --runtime ../site/runtime/v1 --outDir ../site/lesson --emptyOutDir
```

Edit the copied example's content, preview with `npm run dev`, then repeat its `npm run build -- --runtime ...` command to refresh its content and handouts. For example, changing `lesson/gradient.ts` and rebuilding `lesson` updates only `site/lesson/`; `site/basic/` and `site/runtime/v1/` remain unchanged. Add another presentation by installing the same library build and exporting it into another sibling directory with the same `--runtime` path; no source import changes are needed.

Runtime directories are immutable: `slides runtime` refuses to overwrite a populated output directory. Its manifest checks the compiled library's identity and the installed versions of Three.js, KaTeX, and Reveal.js, so two different builds labelled with the same version are not interchangeable. To upgrade the library, create a new directory such as `runtime/v2` from the new installed package, then build the presentations you want to upgrade against it. Keep `runtime/v1` available for existing exports that still reference it.

Topic sections are horizontal Reveal stacks. Their direct children are real vertical slides, one for each scene `step`. Left/right changes topic, up/down changes checkpoint, and Space/Shift+Space traverses the deck. Forward navigation plays an interval; backward navigation, an initial deep link, and overview selection restore its completed state. P pauses/resumes and R replays the active interval without changing the route. Reveal owns keyboard handling, including editable content and browser shortcuts.

Every meaningful pause prints by default. Set `handout: 'final'` for the last checkpoint in each scene, or an array of `topic/scene/checkpoint` IDs. Static slides print once; video uses its poster; audio/custom HTML can provide `printContent`. Backgrounds remain visible in the flat handout. Cmd/Ctrl+P, browser-menu Print, and the shared Print button use the same prepared pages. `?manim-print=1` and Reveal's `?print-pdf` workflow open that same handout directly. All captured fonts load before readiness, including those on unvisited slides. Wait until the preparing screen disappears before printing; native browser print cannot wait for an unfinished initial load.

Printing pauses the active animation and media synchronously and restores their prior playback state afterwards. Opening overview or hiding the tab pauses playback and leaves it paused on return by default. A late scene load cannot replace a newer navigation target. Scene preparation is serialized so rapid navigation allocates at most one pending scene. Each scene factory returns a fresh Scene or ThreeDScene, and the integration disposes its scene when changing modules.

HTML and Markdown helpers accept trusted authored content. Use imported asset URLs (`import poster from './poster.svg?url'`) or files in Vite's public directory so portable builds include them. The starter's `mountPresentation` helper loads Reveal 6's public stylesheet and notes-plugin exports. Applications supplying Reveal 5 can initialize Reveal themselves with that version's CSS paths and use the `manimPresentation` plugin API.

Actual glyph outline drawing requires a vector font (`fontUrl`). Texture-backed Text uses a documented reveal treatment. Settled prose uses selectable HTML; browser formula overlays preserve LaTeX source for accessibility and copying. PDF formulas remain visible graphics, but Chromium may omit the transparent LaTeX overlay from PDF text extraction. The API does not promise arbitrary script shaping or full-document Python LaTeX compatibility.

The integration uses Reveal's documented [plugin lifecycle](https://revealjs.com/creating-plugins/), [two-axis navigation](https://revealjs.com/vertical-slides/), [keyboard bindings](https://revealjs.com/keyboard/), and [native media handling](https://revealjs.com/media/).

Browser regression checks use `npm run test:presentations` after `npx playwright install chromium firefox webkit`. The suite starts a Vite server with live reload disabled, or accepts an existing server through `MANIM_PRESENTATION_TEST_URL`. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to use an installed Chrome executable. Chromium and WebKit cover native keys, deep links, overview/replay, media and print restoration, flat unvisited handouts, and repeated scene disposal. Chromium additionally verifies the actual PDF page count for both print entry points. Firefox is included in the suite; the downloaded Firefox process on the current macOS validation host terminated with SIGKILL before opening a page, so its parity remains unverified.
